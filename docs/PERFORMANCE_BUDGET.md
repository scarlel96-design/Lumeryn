# Lumeryn 경량성·검색 품질·학습 비용 성능 예산

> 상태: 계측 방법 설계. 특정 GPU 성능을 아직 실측하지 않았다.

## 목적

주력 Qwen3.5-4B 파라미터 수를 자동으로 늘리지 않으면서, 검색 정확도·응답 시간·자원 사용량의 균형을 유지한다.

## 예산 범주

| 범주 | 계측 방법 | 초기 정책 |
|---|---|---|
| 기본 모델 | 모델 해시, 양자화, 런타임 | Qwen3.5-4B를 기준선으로 |
| 컨텍스트 | 8K / 16K / 32K | VRAM 및 응답속도 실측 |
| 검색 | 검색 호출·수집 URL·추가 검색 | Fast 1~2 / Balanced 3~5 / Deep 최대 20 (제안) |
| 전문 모듈 | 로드·해제 시간, RAM/VRAM | 필요 시에만 적재 |
| 임베딩/Reranker | 동시/순차 적재 비교 | VRAM 부족하면 순차 실행 |
| GPU 작업 | 시간·Peak VRAM | 학습/벤치마크 충돌 방지 |
| UI | 프레임 p95·입력 지연 | 60FPS 목표, 저하 시 효과 축소 |
| AI 개발 도구 | 공급자별 토큰·쿼터·재작업 | 단독 기본, 효과 입증 후 병행 |

## 벤치마크 매니페스트 필수 항목

`test_dataset_revision`, `time_window`, `hardware`, `driver`, `model_revision`, `quantization`, `vision_processor`, `policy_revision`, `search_provider`, `search_budget`, `latency_p50_p95`, `peak_ram_vram`, `errors`.

성능 비교는 검색 조건과 평가셋을 가능한 동일하게 맞춘다. 데이터를 재수집한 경우 그 차이를 명시한다.

## 승격 금지 조건

- 정확도 개선을 주장하지만 기준 모델·실험 조건을 재현할 수 없음
- 인용 오류 증가 또는 중요한 회귀를 숨김
- 특정 GPU에서 OOM·시간제한 실패를 초래
- 선택 모듈을 끄면 기본 검색 기능이 중단됨
- 성능 숫자를 실제 로그 대신 모델의 설명으로만 제공
